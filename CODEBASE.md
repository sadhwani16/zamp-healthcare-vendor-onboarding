# Zamp PS-2 codebase map

The product accepts a vendor application and five PDFs, reads the evidence,
checks the claims against each other and public US healthcare sources, and
records a decision with the reasons. See [ARCHITECTURE.md](ARCHITECTURE.md) for
the pipeline and decision rules; see [README.md](README.md) to run it.

## The one active request path

`Frontend.jsx` -> `app.py` -> `forensics.py` -> `decision_engine.py` -> `core.py`

- `models.py`: application and extracted-field Pydantic schemas.
- `forensics.py`: native PDF evidence and per-document routing.
- `ocr_engine.py`: local EasyOCR at full rendered resolution; layout and word boxes.
- `openai_models.py`: OpenAI Responses API for ambiguous classification, quoted bank/IRS field suggestions, and vendor message drafts.
- `document_parsers.py`: deterministic W-9, CP-575/147C, bank evidence, CLIA, and COI fields.
- `w9_layout.py`: W-9 EIN cell geometry shared by packet generation and extraction.
- `decision_engine.py`: cross-document rules and the live NPPES client/cache.
- `credibility_and_decision.py`: official LEIE name candidates and precedence.
- `core.py`: active validators and SQLite `vendor_runs`/`run_checks` tables.
- `app.py`: packet intake, five stage events, REST API, and audit persistence.
- `Frontend.jsx`: packet/PDF inspection and a focused five-stage verification
  view. It consumes streamed document/check events, shows decision-driving
  findings by default, and keeps every recorded check in expandable audits.

The historical `db.py` is not part of the public submission or Flask path. The
former `pipeline.py`, `forensics_and_ocr.py`, and `forensics_and_extraction.py`
paths have been removed after moving the parsers and tests to the active path.

## Reference data

`data/oig_exclusions.csv` is downloaded from HHS OIG, with date and SHA-256 in
`data/oig_exclusions.source.json`. It is not generated by the packet script.
`data/npi_cache.json` contains real CMS responses fetched for the packet NPIs;
entries expire after 30 days. Run `python refresh_reference_data.py --oig
--packet-npis` to refresh both sources. Name-only LEIE matches require
confidential identity review.

`data/packets_current` contains scenario fixtures for cases 1-4 and 5A/5B.
Generated PDFs are fixtures and are not issuer-authenticated records.

## What is verified

1. Read all native text or scanned page text; classify and keep the required fields.
2. Incremental PDF text changes, Producer/Creator, and font anomalies.
3. Names, EIN, NPI and ABA checksums, CLIA scope/state, COI limits and dates.
4. CMS NPPES record and taxonomy; official HHS OIG LEIE name candidates.
5. Strict risk > eligibility > unresolved/fixable > approval precedence.

The Flask path is tested by `tests/test_app_pipeline.py`. Controlled services
make the scenario tests deterministic; the real sources have separate metadata
and live lookup behavior. External CLIA, insurer, bank, and IRS issuer
confirmation plus access controls remain production gates, as described in
`ARCHITECTURE.md`.
`tests/test_ein_documents.py` also checks the printed EIN boxes in every packet
and verifies that swapping a W-9 creates a tax-ID mismatch.
